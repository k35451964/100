# 100 — 2100년, 우리 학교 생태지도

고등학교 2학년 「기후변화와 환경생태」 2차시 수업용 사이트입니다. ([12기환02-04] 미래 생태계 변화 예측을, 보고서 찾기 대신 **우리가 만든 생태지도의 변화 분석**으로 바꾼 활동)

- **1차시:** 학생들이 "우리 학교 주변에 있으면 좋겠는 것"을 익명으로 씁니다(키워드). 그다음 [티치타카 AI 생태지도](https://teachitaka.kro.kr)로 학교 주변 생물을 기록합니다.
- **2차시:** 교사가 **[▶ 미래 보기]**를 누르면, 1차시 키워드가 시설이 되어 지도에 와르르 생기고 2100년(고탄소 시나리오)의 생태지도가 만들어집니다.
  - 학생은 **두 생태지도를 비교**하고, 오른쪽 위 **알림**(녹지·불투수면·열섬·온실가스)을 보며 변화의 원인이 기후변화임을 추론합니다.
  - 이어서 생성형 AI로 만든 **포스터를 올려 갤러리로 발표**하고, **익명 별점**(미적 완성도·창의성·문제 해결력, 1~5점)으로 상호평가합니다.

계정은 티치타카 생태지도 계정을 그대로 씁니다(같은 Supabase). 생태지도의 기록은 **읽기만** 하고, 이 사이트의 학반·키워드·포스터·별점은 새 표에 따로 저장합니다.

## 처음 한 번 설정 (순서대로)

1. **GitHub Pages:** 저장소 Settings → Pages → Branch `main` / `(root)` → Save → `https://k35451964.github.io/100/`
2. **카카오 지도:** developers.kakao.com → 내 애플리케이션 → 생태지도 앱 → 플랫폼 → Web 사이트 도메인에 `https://k35451964.github.io` 추가.
   주소를 바꾸면(예: kro.kr) 그 주소도 추가하세요. 등록 전에는 간단한 점 지도로 대신 보입니다.
3. **DB:** Supabase(생태지도 프로젝트) → SQL Editor → New query → `supabase/100_setup.sql` 전부 붙여넣고 **Run**. 여러 번 실행해도 안전합니다.
4. **AI 허용 주소:** Edge Functions → Secrets → `ALLOWED_ORIGINS` = `https://teachitaka.kro.kr,https://k35451964.github.io`
5. **AI 키워드 분류:** Edge Functions → `gemini` → 코드를 `supabase/gemini/index.ts`로 바꾸고 Deploy.
   생태지도의 AI 동정·특징 작성은 그대로이고, `classify_keywords` 작업만 더해집니다. 이 단계를 안 해도 단어 규칙으로 분류할 수 있습니다.

## 수업 순서 (교사)

1. 생태지도 교사 계정으로 로그인 → **새 학반 만들기**(조 수 5) → 화면 오른쪽 위 **참여 코드**를 학생에게 알려 줍니다.
2. **1차시:** 학생이 로그인 → 코드 입력 → 키워드 화면에서 쓰기. 다 쓰면 [🌿 생태지도로 탐사하러 가기].
3. **수업 사이:** ⚙️ 관리에서 아래를 합니다.
   - **조 편성**
   - **지도·기록:** 생물 기록 출처(학반 학생 / 생태지도 클랜 / 지도 범위 안 모든 기록), 날짜, 학교 위치·반지름
   - **키워드 분류:** [🤖 AI로 분류하기] → 확인·수정 → [💾 분류 저장]
4. **2차시:** ⚙️ 관리 → 학반 → **2차시** → 지도 화면에서 **[▶ 미래 보기]**(전자칠판). 끝나면 학생 화면에도 2100년 지도가 열립니다.
5. 학생: [⚖️ 시뮬레이션 전과 비교] → 토의 → 포스터 제작 → [🖼️ 발표]에 조별로 올리기 → 다른 조 별점.
6. 교사: 갤러리에서 **[🏆 결과 공개]**를 누르면 평균과 순위가 모두에게 보입니다. 누가 몇 점을 줬는지는 교사도 볼 수 없습니다.

## 미래 생태지도는 이렇게 계산합니다 (`js/model.js`, 수치는 `js/config.js`)

1. **시설 배치:** 키워드를 AI가 시설 종류·크기로 분류하고 교사가 확인합니다.
   - 크기: 작음 약 1,250㎡ / 중간 약 5,000㎡ / 큼 약 15,000㎡ (대략값). 여러 명이 쓴 키워드는 조금 더 큽니다.
   - 생물이 기록된 곳(녹지) 가운데 학교에 가까운 곳부터 겹치지 않게 놓습니다. 같은 학반은 늘 같은 배치입니다(⚙️ 관리에서 다시 섞기 가능).
2. **서식지 상실:** 시설이 들어선 자리의 생물은 사라집니다. 생물이 기록된 15m 칸을 녹지로 보고, 시설이 덮은 비율을 '녹지 감소'로 셉니다.
3. **도시 열섬:** 녹지가 건물·아스팔트로 바뀐 넓이 1㎢당 +0.24℃입니다(서울 25개 구 분석의 지표면 온도 값).
4. **기후변화:** 2081~2100년 고탄소(SSP5-8.5) 시나리오로 +7.0℃입니다(한반도 평균, 「한국 기후위기 평가보고서 2025」).
5. **생물의 반응:** 티치타카의 모든 기록(다른 학교·지역 포함)에서, 그 생물이 같은 계절(±30일)에 관찰된 날의 가장 낮은~가장 높은 평균 기온을 '견딘 기온 범위'로 봅니다.
   - 미래 기온이 이 범위를 벗어나는 만큼 줄어듭니다(열 안전 여유 개념).
   - 기록이 적은 종은 같은 종류(목본·초본·곤충·기타)의 기록으로 추정합니다.
6. **새로 온 생물:** 우리 학교에는 없는 종 가운데, 같은 계절에 우리보다 따뜻한 곳에서만 관찰됐고 미래 기온이 그 범위에 드는 종입니다.
7. **봄꽃:** 봄 기온 1℃마다 개화가 4.1일 빨라집니다(국내 꽃 7종 연구).

### 확인이 필요한 수치

`js/config.js` 맨 위에 있습니다.

- **`SCENARIO.dT`:** 지금은 한반도 평균값입니다. 기상청 기후정보포털의 학교 소재 구(예: 대구 북구) SSP5-8.5 21세기 후반 값으로 바꾸면 더 정확합니다.
- **`LOCAL_CLIMATE`:** 연평균 기온, 폭염일수입니다. 값을 넣으면 비교 화면 '우리 동네 환경'에 나옵니다.
- **`HEAT_ISLAND.perKm2`:** 지표면 온도 기준입니다. 학교 규모에서는 값이 아주 작게(+0.0x℃) 나옵니다.

## 파일 구조

```
index.html            화면 틀 (외부 도구: supabase-js, 카카오맵)
css/app.css           디자인 (전자칠판·태블릿)
js/config.js          설정값: 서버 주소, 시나리오·열섬·개화 수치, 키워드 종류, 근거 자료   ← 가장 먼저
js/util.js            공용 도우미 (esc, 토스트, 창)
js/model.js           미래 생태지도 계산 (화면과 상관없는 순수 계산)
js/api-live.js        실제 서버(Supabase)와 주고받기
js/api-demo.js        예시 모드(?demo=1) 가짜 데이터
js/map.js             카카오 지도 / 간단한 점 지도
js/keywords.js        1차시 키워드 화면
js/future.js          2차시 지도 화면, 미래 보기 연출, 알림
js/compare.js         시뮬레이션 전과 비교
js/gallery.js         포스터 갤러리·별점·결과·발표 화면
js/teacher.js         교사 관리 창
js/app.js             시작, 로그인, 학반, 화면 전환                 ← 마지막
supabase/100_setup.sql    DB 설정 (한 번 실행)
supabase/gemini/index.ts  AI 서버 함수 (키워드 분류 추가판)
demo/poster-*.png     예시 모드 포스터 그림
```

## 고칠 때 참고

- 사용자가 입력한 값(키워드, 조 이름, 설명, 닉네임)을 `innerHTML`에 넣을 때는 꼭 `esc()`로 감싸 주세요.
- **보안:** 화면의 '교사만' 표시는 버튼용입니다. 실제 권한은 `supabase/100_setup.sql`의 RLS 정책이 지킵니다.
  - 키워드는 쓴 사람을 저장하지 않습니다.
  - 별점은 본인 것만 읽을 수 있고, 평균은 `classroom_poster_results` 함수로만 공개됩니다.
- 내 컴퓨터에서 확인: 이 폴더에서 `python3 -m http.server 8000` → `http://localhost:8000/?demo=1`
